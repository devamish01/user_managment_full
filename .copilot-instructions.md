# Project Instructions - User Management Full Stack Application

## Overview
This is a full-stack user management application with a **Node.js/Express/TypeScript backend** and a **React/TypeScript/Vite frontend**. The codebase follows a **modular architecture** with clear separation of concerns.

## Architecture Principles

### 1. Module-Based Architecture
- **Backend**: Each feature is a self-contained module under `backend/src/modules/`
- **Frontend**: Each feature is a self-contained module under `frontend/src/modules/`
- **Shared Code**: Common utilities, types, and middleware in `backend/src/shared/` and `frontend/src/shared/`

### 2. Barrel Export Pattern
Every module MUST have an `index.ts` that re-exports all public APIs:
```typescript
// backend/src/modules/auth/index.ts
export * from "./constants";
export * from "./controllers";
export * from "./services";
export * from "./types";
export * from "./utils";
export * from "./validations";
```

### 3. Layer Separation (Backend)
```
Module/
├── constants/     # Error messages, success messages, config constants
├── controllers/   # HTTP layer - request/response handling only
├── services/      # Business logic - no HTTP dependencies
├── model/         # Database models (Mongoose)
├── routes/        # Route definitions with middleware
├── types/         # TypeScript interfaces/types
├── utils/         # Module-specific utilities
└── validations/   # Zod schemas for validation
```

### 4. Layer Separation (Frontend)
```
Module/
├── api/           # HTTP client layer (endpoints + API calls)
├── components/    # React components
├── hooks/         # Custom React hooks
├── pages/         # Page-level components
├── routes.tsx     # Route definitions
├── services/      # Business logic layer
├── store/         # State management (useSyncExternalStore)
├── types/         # TypeScript interfaces
├── utils/         # Module-specific utilities
└── shared/        # Shared components/types within module
```

## Backend Coding Standards

### Controllers
- Use `asyncHandler` wrapper for all async controllers
- Use `successResponse` / `createdResponse` / `errorResponse` from `@/shared/response`
- Controllers should ONLY handle HTTP concerns (request parsing, response formatting)
- Delegate all business logic to services

```typescript
// ✅ Good controller pattern
export const getUsersController = asyncHandler(
  async (req: Request, res: Response): Promise<Response> => {
    const result = await getUsers(req.query as any);
    return successResponse<IUser[]>({
      res,
      message: USER_MESSAGES.FETCH_SUCCESS,
      data: result.data,
      meta: { pagination: result.pagination, stats: result.stats },
    });
  },
);
```

### Services
- Pure business logic, no Express dependencies
- Throw `AppError` for operational errors
- Return data, not HTTP responses

```typescript
// ✅ Good service pattern
export const getUsers = async (query: UserQueryParams) => {
  // Business logic here
  const users = await User.find(filter).skip(skip).limit(limit);
  return { data: users, pagination, stats };
};
```

### Error Handling
- Use `AppError` class for all operational errors
- Include `statusCode`, `errorCode`, and `message`
- Use constants from `HTTP_STATUS` and module-specific error messages

```typescript
throw new AppError({
  message: AUTH_MESSAGES.INVALID_EMAIL,
  statusCode: HTTP_STATUS.UNAUTHORIZED,
  errorCode: "INVALID_EMAIL",
});
```

### Validation
- Use Zod schemas in `validations/` folder
- Apply validation via `validate` middleware in routes
- Export schemas AND types from module index

### Routes
- Define routes in `routes/*.route.ts`
- Apply middleware: `authMiddleware`, `validate({ body: schema })`, `validate({ query: schema })`
- Export router as `moduleRoutes` (e.g., `authRoutes`, `userRoutes`)

### Database (Mongoose)
- Models in `model/index.ts`
- Use `userId` (string) as primary identifier, not `_id`
- Include timestamps, soft delete if needed

## Frontend Coding Standards

### API Layer
- **Endpoints**: Constants in `api/endpoints.ts` (URLs only)
- **API Class**: `AuthApi` class with static methods in `api/auth.api.ts`
- **Service Class**: `AuthService` class that wraps API calls and unwraps responses

```typescript
// ✅ API layer pattern
export class AuthApi {
  static login(credentials): Promise<ApiResponse<{ session: Session; user: User }>> {
    return api.post<{ session: Session; user: User }>(LOGIN, credentials);
  }
}

export class AuthService {
  static async login(credentials): Promise<AuthSession> {
    const res = await AuthApi.login(credentials);
    if (!res.success || !res.data) throw new Error(res.message || "Login failed");
    return res.data.session;
  }
}
```

### State Management
- Use `useSyncExternalStore` for module-level state (singleton pattern)
- Store in `store/*.store.ts`
- Export hook `useAuthStore` (or module name)

```typescript
// ✅ Store pattern
const listeners = new Set<Listener>();
let state: AuthState = { ... };

export const useAuthStore = () => useSyncExternalStore(subscribe, getSnapshot);
```

### Routing
- Define routes in `routes.tsx` using React Router v6 `RouteObject[]`
- Use `PermissionGuard` for protected routes
- Export as `moduleRoutes` (e.g., `usersRoutes`, `rolesRoutes`)
- Route config helpers for URL generation

### Components
- Page components in `pages/`
- Reusable components in `components/`
- Use `PermissionGuard` for permission-based rendering

### Types
- Define in `types.ts` or `types/` folder
- Export from module index
- Share common types via `@/lib/types`

## Shared Code Patterns

### Backend Shared (`backend/src/shared/`)
- `response/` - Standardized response helpers
- `errors/` - `AppError` class and error formatting
- `middlewares/` - `asyncHandler`, `validate`, `authMiddleware`, `errorMiddleware`
- `constants/` - HTTP status codes, common constants
- `logger/` - Winston logger
- `database/` - Mongoose connection
- `types/` - Common TypeScript types
- `utils/` - Common utilities

### Frontend Shared (`frontend/src/shared/`)
- `providers/` - React Context providers (AppProviders)
- `layouts/` - Layout components (AdminLayout)
- `components/` - Reusable UI components
- `hooks/` - Common hooks
- `utils/` - Common utilities (cn, etc.)
- `types/` - Shared TypeScript types
- `constants/` - Shared constants

## Naming Conventions

| Element | Convention | Example |
|---------|------------|---------|
| Files | kebab-case | `user.controller.ts`, `auth.api.ts` |
| Classes | PascalCase | `AuthService`, `AppError` |
| Functions/Variables | camelCase | `getUsers`, `userId` |
| Constants | UPPER_SNAKE_CASE | `HTTP_STATUS`, `AUTH_MESSAGES` |
| Types/Interfaces | PascalCase | `User`, `AuthState` |
| Route exports | camelCase + Routes | `authRoutes`, `userRoutes` |

## Import Aliases
- Backend: `@/` maps to `backend/src/`
- Frontend: `@/` maps to `frontend/src/`

```typescript
// Backend imports
import { successResponse } from "@/shared/response/index.js";
import { AppError } from "@/shared/errors/index.js";
import { asyncHandler } from "@/shared/middlewares/index.js";

// Frontend imports
import { api } from "@/core/api";
import { useAuthStore } from "@/modules/auth/store";
import { PermissionGuard } from "@/router/guards/PermissionGuard";
```

## Adding New Modules

### Backend Module Checklist
1. Create folder structure under `backend/src/modules/<module>/`
2. Create `constants/`, `controllers/`, `services/`, `model/`, `routes/`, `types/`, `utils/`, `validations/`
3. Create `index.ts` with barrel exports
4. Create model in `model/index.ts`
5. Create validation schemas in `validations/`
6. Create services in `services/`
7. Create controllers in `controllers/`
8. Create routes in `routes/<module>.route.ts`
9. Export routes in `routes/index.ts`
8. Register routes in `backend/src/routes/index.ts`

### Frontend Module Checklist
1. Create folder structure under `frontend/src/modules/<module>/`
2. Create `api/`, `components/`, `hooks/`, `pages/`, `services/`, `store/`, `types/`, `utils/`
3. Create `index.ts` with barrel exports
4. Create endpoints in `api/endpoints.ts`
5. Create API class in `api/<module>.api.ts`
6. Create service class in `services/<module>.service.ts`
7. Create store in `store/<module>.store.ts`
8. Create routes in `routes.tsx`
9. Create pages/components
10. Register routes in `frontend/src/router/routes.tsx`
